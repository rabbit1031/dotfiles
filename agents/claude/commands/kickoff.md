あなたはタスクの立ち上げ（kickoff）を担当します。`$ARGUMENTS` で渡された依頼を、以下の手順で再現性のあるフローに乗せてください。

## 1. 関連タスクの検索

`mcp__claude_ai_Notion__notion-search` で「Tasks」を検索し、Tasks データベースを特定してください。
次に、そのデータソース URL を `data_source_url` に指定して `$ARGUMENTS` に関連するキーワードで Tasks 内を検索してください。

候補が見つかった場合は `AskUserQuestion` でユーザーに確認してください（options は最大4件。候補がそれ以上ある場合は関連度の高いものを優先）。

- **候補あり・選択あり**: 選択されたタスクと今回の作業を紐付けて以降のステップを進める
- **「なし（新規）」を選択 or 候補なし**: そのまま構造化（2.）に進む

## 2. 構造化・補完

### 2.1. 構造化

依頼を以下の4項目に構造化してください。

- **目的**: 何を達成したいか（Why / What）
- **背景・制約**: 前提、技術スタック、守るべき制約
- **成果物**: 完成時に何が存在するか（ファイル、PR、ドキュメント等）
- **完了条件**: 何をもって「完了」とするか（テスト PASS、レビュー通過等）

### 2.2. セルフレビュー

補完に進む前に、構造化した4項目を批判的に見直してください。

- 依頼の本質を正確に捉えているか（範囲の過不足はないか）
- コードベース・文脈から自力で埋められる項目が残っていないか

問題があれば 2.1. を修正してから進むこと。

### 2.3. 補完

上記4項目のうち、依頼内容から一意に定まらない箇所を引き出してください。

- コードベース・文脈・妥当な既定値から判断できる項目は質問せず、自分で調査して埋めてください。
- ユーザーの判断が必要な箇所は **一問ずつ** 質問し、それぞれに自分の見解を添えてください。選択肢が明確な場合は `AskUserQuestion` を使って構いません。

### 2.4. セルフレビュー

計画・分解に進む前に、補完で得た情報を踏まえて全体を見直してください。

- 構造化した4項目に矛盾・見落としがないか
- ユーザーへの確認事項が漏れていないか

問題があれば 2.3. に戻って補完を続けること。

## 3. 計画・分解

Plan Mode を活用してゴール達成までの計画を立て、`TodoWrite` でタスクに分解してください。

## 4. 外部保存（Notion 起票）

構造化プロンプト・補完で得た情報・タスク分解を本文にまとめ、Notion の Notes データベースに起票してください。

本文を作成する前に `Skill(notion-style)` を呼び出し、文体ガイドラインを確認すること。

- ツール: `mcp__claude_ai_Notion__notion-create-pages`
- 親（parent）: `notion-search` で「Notes」を検索し、メモ管理用のデータベースを特定してそのデータソース URL を使うこと
- プロパティはデータベースのスキーマに従い、以下を設定すること:
  - タイトル（Name）: 簡潔な作業名
  - Category: 依頼の内容から適切な値を判断して設定する。判断が難しい場合は 2.3. で確認すること
  - Tags: `🤖 w/ Claude Code` を必ず含める（既存タグに無ければ新規追加）
- 本文構成: `## 目的` / `## 背景・制約` / `## 成果物` / `## 完了条件` / `## タスク分解`

**重要**: 書き込みは外向きアクションです。作成するページの本文とプロパティを先にユーザーに提示し、**承認を得てから** `notion-create-pages` を実行してください。

起票後、作成されたページの URL を出力し、「完了時は `/wrapup` でこのページを更新する」と伝えてください。
